# Троичные лампочки (`/ternary`)

Вторая версия приложения: ряд лампочек для обучения детей **троичной** системе
счисления. Функционально повторяет бинарную версию из корня (`/`), отличается
только системой счисления и тремя состояниями лампочки вместо двух.

## Как считает

Каждая лампочка — один троичный разряд. Самая правая означает `1`, левее `3`,
ещё левее `9`, `27` и так далее (каждый шаг влево умножает вес разряда на 3).

Состояние лампочки кодируется тем, как она горит:

| Свет | Значение разряда |
| --- | --- |
| погашена | `0` |
| горит наполовину (нижняя половина) | `1` |
| горит полностью | `2` |

Клик по лампочке циклически перебирает состояния: `0 → 1 → 2 → 0`.

Подсчёт — свёртка слева направо: `value = value * 3 + разряд`. Для точности при
большом числе лампочек используется `BigInt`.

Пример: разряды слева направо `0 0 1 0 2` → `Результат: 11 (00102)`.

## Ключевой принцип

Приложение — цифровая модель лампочек для счёта, а не подсказчик:

- итог во время игры не отображается;
- итог вычисляется только по кнопке «Проверить» и служит проверкой, а не
  подсказкой; после «Проверить» игра продолжается;
- веса разрядов не подписаны, переносы не показываются, разбор суммы не
  выводится.

## Правила

- Изначально 5 лампочек, все погашены; столько же после «Начать заново».
- «Добавить лампочку» добавляет одну погашенную лампочку слева (новый старший
  разряд). Количество не ограничено, ряд прокручивается по горизонтали.
- Крестик удаления есть у каждой лампочки, удалить можно все; пустое поле —
  допустимое состояние, «Проверить» показывает `Результат: 0 (0)`.
- При удалении из середины разряды пересчитываются по позиции.
- Любое действие с полем (переключение, добавление, удаление, сброс) скрывает
  ранее показанный итог.
- Ряд выровнен по правому краю; ширина от 1024px, в `viewport` задано
  фиксированное значение `1024`.

## Доступность

- лампочка — кнопка с `aria-label` вида `Лампочка 3 из 5, значение 1 — горит
  наполовину` и атрибутом `data-value` для стилей;
  `aria-pressed` не используется: он описывает только два состояния;
- крестик — кнопка с `aria-label` «Удалить лампочку», видна всегда;
- у всех интерактивных элементов виден фокус, всё доступно с клавиатуры;
- блок с итогом имеет `aria-live="polite"`, результат озвучивается скринридером;
- при смене маршрута заголовок документа меняется на «Троичные лампочки».

Стили версии намеренно продублированы с префиксами `.tapp`, `.tbulb-*`,
`.tcontrols`, `.tresult`, чтобы классы не пересекались с бинарной версией.

## Полугорящая лампочка

SVG имеет `viewBox="0 0 120 160"`, его середина — `y = 80`. Лампочка собрана из
двух слоёв, ссылающихся на одну и ту же геометрию из `<defs>` (через `<use>`):

- непустой слой — серая колба и тёмная нить накала, нарисованные целиком при
  любом разряде;
- светящийся слой (`__glass-lit`, `__filament-lit`) — жёлтая колба, тёплая нить
  и свечение, рисуется только при разряде `1` или `2`.

При разряде `1` на светящемся слое стоит `clip-path` с прямоугольником
`y = 80 … 160`. Визуально картинка лампочки буквально разрезается по горизонтали:
нижняя половина (стекло, свечение, низ нити накала) горит, верхняя остаётся
тёмной. Лучи света (в верхней части) при этом не загораются — они включаются
только при разряде `2`.

Одиночная колба с одним `clip-path` здесь не годится: она вырезала бы верхнюю
половину целиком, и лампочка выглядела бы пустой половинкой колбы.

Идентификаторы `clipPath` и путей в `<defs>` строятся из `id` лампочки
(`tbulb-half-{id}`) — иначе при нескольких лампочках на поле возникли бы
дублирующиеся `id` в DOM. Ссылка на `clipPath` передаётся в CSS через переменную
`--half-clip` на корневом `<svg>`.

Цоколь, резьба и контакт остаются металлическими во всех состояниях: горение
металлической части лампы выглядело бы неверно.

## Роутинг

Маршрут подключён в `src/main.tsx`:

```tsx
<BrowserRouter>
  <Routes>
    <Route path="/ternary" element={<TernaryApp />} />
    <Route path="*" element={<App />} />
  </Routes>
</BrowserRouter>
```

Бинарная версия осталась на `/` и на любом неизвестном пути. Навигационных
ссылок между версиями нет — переход только по прямой ссылке `/ternary`.

При раздаче собранного `dist` статикой сервер должен отдавать `index.html`
для `/ternary` (SPA fallback). `vite dev` и `vite preview` делают это сами.
